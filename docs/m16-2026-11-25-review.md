## What cannot be established

The old shared Yahoo fetcher collapsed network, HTTP and chart-response failures
into `None`. The audit therefore cannot distinguish throttling, rejected cookies,
empty upstream charts or another transport failure. It does NOT prove HTTP 429.
Nor does a workflow staying alive prove that timely prices were available.

## Corrective changes

1. Yahoo remains the only M16 provider. Try the existing one-day chart path, then
   a five-day window when the first response is empty/stale. Filter the result
   back to today's session; older bars never become today's entries.
2. Preserve sanitized host/HTTP/error-category diagnostics via an optional shared
   fetch callback. Default behaviour for other runners is unchanged. M16 uses
   shorter per-request timeouts so failed requests release workers sooner.
3. Do not retry a second range to cure authentication/rate-limit failures. A
   detected HTTP 429 triggers a shared 30-second M16 cooldown. Consecutive
   per-symbol failures back off up to 30 seconds; healthy active polling stays at
   its one-second target. No Dhan API is required.
4. Retry incomplete discovery beyond the first 30 seconds of a candle boundary,
   instead of leaving unseeded stocks untouched until another boundary. The
   freshness budget itself is NOT widened.
5. Separate receipt recency from request-start finality: a ten-second response is
   not automatically excluded from running observation just because it exceeded
   five seconds. It must have arrived within five seconds, have taken at most
   30 seconds, and satisfy the model's current-candle checks. Requests started
   before close still cannot certify that candle's final OHLC.
6. Exclude unaligned trailing Yahoo quote timestamps (e.g. 14:26:13) from candle
   coverage. Do NOT round them into fabricated five-minute candles. The old
   report advertised those rows as the latest usable data before normalization
   discarded them.
7. Preserve outage episodes across successful recovery, sample repeated failures,
   and print minute-by-minute progress counts. Upload end-of-job diagnostic
   artifacts even on failures, independently of the Git state-push step.
8. Keep missing morning discovery unhealthy after 11:00 even when no setup was
   seeded. Store the affected symbols, exact reasons, expected candle and cursor.
   The first operational warning includes a few named examples; repeated notices
   remain suppressed as requested. Monitoring records continue updating.
9. Make the audit executive summary concise and current, keeping detailed
   per-symbol evidence in the complete appendix. Explicitly warn that late
   backfill is not complete missed-opportunity reconstruction.

## Limits and operational checks

This patch improves recovery and observability; it cannot manufacture prices
while Yahoo is unavailable or guarantee exchange-time detection with OHLC
polling. Eight fetch workers still share active requests, so one-second scheduling
is not a one-second full-universe SLA. No live Yahoo/Telegram validation is
possible from this sandbox. Check actual published candle/analysis timestamps and
progress output next session, not only whether the workflow says running.

The rally, EMA, pullback, BOS, cutoff and no-backdating rules remain unchanged.
